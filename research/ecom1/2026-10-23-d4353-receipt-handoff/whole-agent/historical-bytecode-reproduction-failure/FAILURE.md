Root independently ran the documented reproduce.py command with the pinned Python runtime and without PYTHONDONTWRITEBYTECODE. It failed the source-pins.json byte-equality assertion because importing lzpack created an upstream/__pycache__ file, and prepare.py included all upstream files in the pin set. Earlier successful reproduction had disabled bytecode externally. This was a packaging/reproduction defect; it did not change candidate behavior or existing test results. The fix excludes __pycache__ and bytecode files from input collection/copying and sets PYTHONDONTWRITEBYTECODE=1 explicitly for child processes.
