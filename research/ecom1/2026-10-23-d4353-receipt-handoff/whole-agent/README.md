# Whole-agent receipt handoff mechanism tests

All 336 complete-source executions pass (168 CPython,168 native Monty1.2.0): 128 ablation executions and208 fresh gate executions. Exact d4353 parent is compared with candidate `1594a8403c660542dca851898ffc17a9cd0dd999f34dc854b09acf94f169497f` (64,701 bytes). Both readable and exact packed source forms are used. Native runs use method-only `ClassInstance` and10-second feed/turn,1000-suspension limits. No production source was edited here, no model or live SDK call was made, and no task-grade gain is established.

The two input worlds are exact historical d4702 t023/t063 observed RPC responses, independently reconstructed and CAS-verified in `2026-10-23-d4702-receipt-worlds`. They are used as host responses for current d4353 parent/candidate executions. This is not a claim that these generated inference requests equal d4702's historical requests. Source copies, world/context copies, fixed historical model response bodies and all captured generated requests are retained. No unmatched RPC is silently filled: unmatched requests fail the run. The host can derive a complete shallow subtree from actual `/proc` Tree if needed, but **none of these336 executions uses that branch**. Default-equivalent Read options return the same exact archived response.

The four ablation arms are parent, combined prototype, context-only, and provenance-only. Context-only removes exactly the new `note_policy_read` invocation from the transfer helper. Provenance-only changes exactly its final return to retain the original messages. These two diagnostic-only source variants are rebuilt and packed from the pinned prototype, with readable/decoded AST equality checks. They are not proposed deployment candidates. Original parent and combined candidate files are untouched. Each arm runs both worlds with historical final response, fixed OK, fixed denial, and fixed clarification replies. Router replies are exact historical bytes throughout; fixed final replies intentionally do not react to the changed context.

All four arms make identical132 ECOM requests in the actual-world cases, consisting only of archived Read/List/Tree and `/bin/id`/`/bin/date` calls. There are no Write/Delete/extra Exec calls or additional reads introduced by the handoff. The combined/context-only main requests contain the parent's original eight messages followed by two exact observed Reads (availability policy and the actual upload), including actual metadata and verified content hashes. Provenance-only has exactly the parent's requests. All source forms/runtimes have identical calls, requests and final answers within each arm/case.

The ablation separates deterministic citation behavior from context effects. For every fixed reply, combined and provenance-only final answers are identical; parent and context-only final answers are identical. In t023's historical frozen `FALSE(2)` reply, provenance adds the upload, two recognized product references, and availability policy. In t063's frozen employee-denial reply, the denial remains unchanged and availability policy is added; the upload is not added for that outcome. Thus the t023 citation gain can occur without delivering extra model context. Nothing in these tests demonstrates that context transfer fixes the model's mistaken employee/purchase interpretation.

Fresh controls are explicit host overlays, captured with before/after responses in `gate-results.json`: no receipt request, nonemployee identity, appended manager-override wording, no upload, ambiguous upload listing, explicitly named actual upload, successful clean receipt, changed availability policy, failed policy Read, failed upload Read, truncated policy, truncated upload, and missing yes/no tokens. Every control compares exact parent and combined source across two worlds and four source/runtime forms. All calls are identical between parent and candidate for each control. Declined gates and helper success have identical inference requests and answers. Named upload transfers the exact named file. Truncated-read controls omit that content from the appended context, retain explicit incomplete metadata, and do not newly cite that incomplete source; the complete other source may still be transferred/cited.

The helper-success upload is synthetic, using an exact product SKU/price and an open store name/address from that same archived world. Product/store primary files are untouched. It is a deterministic helper-path control, not a reconstruction of a real transaction. Both versions finish before main-loop inference (one router call); their own original answer-token conventions are preserved. Failed-read controls raise a declared scripted RuntimeError, not an invented historical failure.

`analysis.json` contains eight parallel ablation summaries and asserts exact transferred content/metadata, RPC parity, context/provenance separation and truncated-source behavior. Full requests, actions, stdout and diagnostic overlays remain in `results.json`/`gate-results.json`. There are no foreign/shared caches: each execution gets a fresh host/world copy and fresh Python globals or Monty session.

Run `python prepare.py`, `python replay.py`, `python gates.py`, `python analyze.py` with pydantic-monty1.2.0 and the pinned packer (Python3.14.3 used here). `python reproduce.py` runs them in a temporary copy and checks every output byte. The outer receipt-world package preserves the full original traces; these local world copies are sufficient to reproduce these offline tests. Separate structural/wire reviews cover message conflicts, size pressure and conditional request-object size estimates; no private-wire verification was performed. This package does not claim exhaustive grammar/semantic coverage or provider behavior.
