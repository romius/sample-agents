## Pre-payment gaps

The current PLAN usefully separates final presence, strict schema, source-parser acceptance and evidence-supported next actions. However, this package currently does not pin the actual d4702/d4955 action-parser implementation or provide a fixture-specific frozen adjudication sheet. To make the promised readout reproducible before seeing outputs, pin the source/parser versions (or explicitly mark parser acceptance unverified), define strict-schema rules independently, and record the visible-evidence limits for each fixture. Record unsupported final assertions, wrong/missing qualifications, proposed mutation and unresolved evidence separately. A syntactically valid Read or catalog lookup can be useful without completing the task; a report_completion or Write can be well-formed yet unsupported. No arbitrary output string should be promoted into an executed action.

Preserve initial partially blinded judgments before revealing effort labels; authors already know the design, so do not claim full blinding. Retain disagreements and unknowns. A low empty-final count, a parser-accepted action, or a superficially successful equal-input control alone cannot justify an agent change or aggregate score claim. The PLAN's conservative decision rule is appropriate once these definitions are frozen. This review does not authorize submission.
