# Frozen paired SKU next-action diagnostic

This is a diagnostic runner, not an ECOM1 task-solving agent or a promotion candidate. One short-queue carrier trial makes 16 logical LLM calls over four frozen cases × two observation arms × two repeats. It performs no ECOM-world RPCs and ends the carrier with OUTCOME_NONE_UNSUPPORTED. Its benchmark grade is irrelevant. This efficiently resolves whether the new evidence changes the model's immediate decision without submitting another full100 or comparing different generated worlds.

Hypothesis: the bounded sibling attachment helps the model retain unresolved qualifiers and distinguish actual compatible variants, without forcing clarification for an exact SKU or a unique explicitly compatible kit. Their catalogue observations are asserted identical to current parent world_tool on exact archived101-product catalogues. Two derived controls change the original user request, assistant query and resulting parent catalogue observation coherently on the same frozen DeWalt catalogue/policy/identity. They are not exact historical executions. No historical model response is replayed as new outcome evidence.

Within every pair only the candidate's actual sku_lookup_evidence field differs. Original matches, order, scores and every other message are unchanged. The treatment uses the original user description. Inference settings are equal: GPT-OSS-120B, DeepInfra BF16, medium reasoning, temperature0, max_tokens2048, nonstreaming, no seed. SDK0.3.7 pins the provider and forbids provider overrides, so archived provider/stream fields are omitted from SDK arguments but retained in the raw upstream archive. Backend drift and small-sample randomness remain possible; arm order is counterbalanced within every case and interleaved across cases. Complete pair requests, hashes and order are fixed in fixtures.json.

Predeclared interpretation (criteria also in fixtures.json):

- Case ambiguity: two DeWalt kits explicitly have a case. A final clarification naming both relevant SKUs is a correct immediate final decision; a forced unique SKU is incorrect. Another relevant retrieval is deferred, not a demonstrated pass.
- Standard head: choosing FLAT from lexical score is incorrect. The actual records do not positively establish the standard-head qualifier; clarification preserving that uncertainty is appropriate. Further relevant retrieval is deferred. Do not turn missing words into negative product properties.
- Exact SKU: return the named existing 2AH SKU with its exact catalogue reference when no contradictory qualifier is present. Unnecessary clarification is a control regression; further retrieval remains deferred.
- Unique variant: actual kit fields distinguish2x2.0Ah batteries and case from5.0Ah and body-only. Return2AH with its reference. Do not declare ambiguity merely because siblings exist.

For every raw output retain finish reason, usage, schema validity, selected action, message, outcome, SKU/reference set and error. Classify immediate final decisions as correct/incorrect, new relevant retrieval as deferred, other tools as unexpected action, invalid JSON/action as malformed and provider exception as error. Record truncation separately. Parse only one complete JSON action (allow a single enclosing JSON code fence); extra generated actions or prose are malformed for this diagnostic. Do not execute generated actions or infer a final result after a deferred response. No selective omission, after-the-fact threshold changes, significance claim or full-task causal claim. Two repeats do not estimate a general effect size. Negative-qualifier, contradictory-SKU, missing-attribute and multi-observation history-budget effects remain untested by this small diagnostic.

Before dispatch: build.py, verify.py, independent review, exact sources/tests/dependencies/results in Git and Brain, size/hash check. Eight fake-host executions verify readable/packed parity, all16 exact ordered requests, failure recording and single final answer under native10-second/1000-suspension limits. No real model calls were made by those checks. SDK eligible429 retries may increase provider attempts; there is no custom retry.

Run `sh reproduce.sh` from any directory with the pinned uv cache available. Dependencies and earlier archive references are explicit in DEPENDENCIES.json.
